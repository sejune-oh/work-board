# 디자인 기준

업무 보드의 화면은 모두 이 문서를 따릅니다. 새 화면, 새 컴포넌트, 기존 화면 손질 모두 해당합니다.
기준을 바꿀 때는 이슈를 먼저 만들고 이 문서와 `web/src/app/globals.css`를 같은 PR에서 고칩니다.
지금 기준은 v3(#48)입니다. 합의 과정과 이전 화면과의 차이는 [design-v3-proposal.md](design-v3-proposal.md)에 있습니다.

## 1. 방향

**목적.** 10명 안팎의 팀이 "누가, 어느 프로젝트에서, 무엇을, 어디까지" 하는지 한눈에 보게 합니다.
매일 여는 사람은 개발자가 중심이지만, 기획, 디자인, 운영 담당도 같은 화면을 봅니다.

**톤: 조용한 작업대.** 개발자가 하루 종일 켜 두는 도구처럼 보입니다. 차가운 회색 바탕 위에 흰 판(카드) 몇 장을 놓고,
그 안의 표와 목록이 주인공입니다. 위계는 **글자 크기, 굵기, 여백**으로 만들고 선은 최소로 씁니다.
판은 테두리 선 대신 옅은 고리(ring)로 바탕과 나뉩니다. 그라디언트, 종이 질감, 장식 그림자를 쓰지 않습니다.

**기억에 남을 한 가지: 주홍 깃발과 거터는 "여기를 보세요"에만 씁니다.**
화면 전체가 회색과 흰색으로 차분하고, 주의가 필요한 곳(긴급, 오래 멈춘 일, 담당자 없음, 리뷰 대기)에만
주홍색 깃발이 나옵니다. 긴급인데 아직 시작 전인 줄에는 코드 diff의 변경 표시처럼 왼쪽에 3px 주홍 거터가 붙습니다.
버튼, 링크, 선택 상태에는 주홍을 쓰지 않습니다. 강조색이 곧 경보색이라 의미가 흐려지지 않습니다.

**한 문장 현황.** 개요 화면 맨 위에는 숫자 묶음 대신 사람이 쓰는 문장 하나를 둡니다.
예: "긴급 2건 중 1건은 아직 시작 전이고, 리뷰를 기다리는 PR이 3건 있습니다."
가장 중요한 사실을 쉬운 한국어로 먼저 말하는 것이 이 제품의 목소리입니다.

**왜 이 방향인가.**

- 매일 쓰는 도구의 문법(표, 거터, 단축키, 고정폭 번호)을 따라야 개발자가 낯설어하지 않습니다.
- 한글 문장은 비례폭(IBM Plex Sans KR)과 넉넉한 줄 간격으로 두어 기획·운영 담당도 편하게 읽습니다.
- 색을 줄이고 주의 색 하나만 남기면 10초 안에 "손봐야 할 곳"이 보입니다.
- 선을 줄이고 간격으로 묶으면 같은 정보가 더 가볍게 읽힙니다.

## 2. 글꼴과 글자 단계

모두 Google Fonts에서 받습니다(`next/font/google`, `--font-plex-kr`, `--font-plex-mono`). 글꼴은 두 가지뿐입니다.

| 역할 | 글꼴 | 굵기 | 쓰는 곳 |
| --- | --- | --- | --- |
| 본문·표제 (sans) | **IBM Plex Sans KR** | 400, 500, 600, 700 | 모든 글자 |
| 고정폭 (mono) | **IBM Plex Mono** | 400, 500, 600 | **ASCII만**: 저장소 이름과 번호(`booking-api #102`), PR 번호, 핵심 숫자, 단축키 |

**Mono는 ASCII에만 씁니다.** Plex Mono에는 한글이 없어 한글이 섞이면 대체 글꼴로 그려지면서 칸이 벌어집니다.
날짜와 경과(`11월 10일`, `1일 전`, `3d ago`)는 Sans로 쓰고 `tabular-nums`로 자리를 맞춥니다. 숫자 하나만 Mono로 감싸는 것은 됩니다.

크기는 언어와 상관없이 같고, **줄 간격은 언어에 따라 다릅니다**(한글은 받침과 획이 세로를 채워 더 넓게).
`<html lang>`이 바뀌면 `:root[lang="en"]`의 값이 적용됩니다. 줄 간격은 px로 고정해 4px 격자에 맞춥니다.

| 단계 (클래스) | 크기 | 줄 간격 ko | 줄 간격 en | 굵기 | 자간 | 쓰는 곳 |
| --- | --- | --- | --- | --- | --- | --- |
| `text-display` | 32px (≤639: 24) | 44px (≤639: 34) | 40px (≤639: 30) | 600 | ko -0.02em, en -0.025em | 한 문장 현황, 들어가기 전 화면 제목 |
| `text-title` | 22px (≤639: 20) | 32px (≤639: 30) | 28px (≤639: 26) | 600 | ko -0.012em, en -0.015em | 화면 제목, 이슈 패널 제목 |
| `text-heading` | 15px | 24px | 22px | 600 | -0.005em | 카드 머리, 구역 제목 |
| `text-body` | 15px | 26px | 24px | 400 | 0 | 문장, 설명 |
| `text-ui` | 14px | 22px | 20px | 500 | 0 | 표·목록 줄의 제목, 메뉴, 이슈 카드 제목 |
| `text-small` | 13px | 20px | 18px | 400 | 0 | 보조 설명, 상태 이름, 사람 이름, 날짜·경과 |
| `text-meta` | 12px | 16px | 16px | 400 / 500 | 0 | Mono 번호, 깃발, 작은 표지 |
| `text-figure` (Mono) | 34px (≤639: 28) | 40px (≤639: 32) | 같음 | 500 | -0.03em | 핵심 숫자 |

- 표제(`h1`, `h2`)는 `text-wrap: balance`, 한글은 `word-break: keep-all`.
- 13.5px 같은 반 픽셀 크기와 `text-[12.5px]` 같은 임의 크기를 쓰지 않습니다. 위 단계에서 고릅니다.
- 자간을 넓힌 작은 머리말(eyebrow)은 쓰지 않습니다. 맥락은 제목 위 `text-small` `muted` 한 줄로 줍니다.

## 3. 색

색은 세 무리입니다. **회색 바탕**, **상태**(5색), **주홍**(주의). 프로젝트 색(DB의 `projects.color`)은
10px 사각 표식에만 쓰고 넓은 면에 칠하지 않습니다. 대비는 WCAG 2.x, `surface` / `canvas` / `sunken` 순서입니다.

상태 색 규칙:

- 상태 색은 점(8px 원)과 막대 조각에만 씁니다. 글자 색이나 넓은 배경으로 쓰지 않습니다.
- 상태는 언제나 **점 + 이름**을 같이 씁니다. 색만으로 구분하지 않습니다(색각 이상 대비).
- 완료 항목은 `muted` 글자로 한발 물러섭니다. 취소는 회색 점 + 제목 가운데 줄, 완료 열 아래 접힌 묶음.
- 글자 색 토큰은 `canvas`, `surface`, `sunken`, `accent-wash` 위에서 4.5:1 이상입니다. 바꿀 때는 대비를 다시 계산합니다.

주홍과 버튼 규칙:

- 주홍이 화면에 나오는 곳은 주의 표시뿐입니다(5장의 "주의 표시"). 오류도 주홍을 쓰지 않습니다.
- 한 문장 현황의 주의 숫자는 주홍 글자로만 씁니다. "7일 넘게 멈춤" 칸은 0보다 크면 위쪽 2px 주홍 줄 + 주홍 숫자.
- 한 화면에서 주홍이 칠해진 면(`accent-wash`)은 2~3곳을 넘기지 않습니다.
- **주 버튼은 잉크색**입니다. 화면마다 주 동작 하나(로그인, 다시 확인, 다시 시도, 이후 회사 만들기)만
  `btn btn-primary`(`ink` 바탕 + `on-ink` 글자). 나머지 버튼은 `btn`(`surface` 바탕 + 고리).
- 링크는 `ink` 글자 + `rule-strong` 밑줄(`.link`)입니다.

## 4. 간격, 모양, 높이, 움직임

**간격**은 4px 단위: `4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80`.

| 자리 | 값 |
| --- | --- |
| 화면 좌우 여백 | 40 (≥1024) / 24 (640~1023) / 16 (≤639) |
| 내용 최대 폭 | 1200px, 가운데 |
| 카드 안쪽 | 20 (≤639 숫자 판은 16) |
| 카드 사이, 구역 사이 | 24 |
| 화면 머리 → 첫 카드 | 32 |
| 표 줄 | 위아래 12 (한 줄 46px 안팎). 접힌 줄은 위아래 16 |
| 묶음 머리 위 | 20 |

**모서리**

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `rounded-mark` | 3px | 프로젝트 표식 |
| `rounded-flag` | 4px | 깃발, `kbd` |
| `rounded-control` | 8px | 버튼(40px), 메뉴 줄, 검색창, 토글 |
| `rounded-item` | 10px | 큰 버튼·입력(48px), 이슈 카드, 점선 상자 |
| `rounded-card` | 12px | 카드 |
| `rounded-sheet` | 16px | 들어가기 전 화면 카드, 이슈 패널(왼쪽 모서리) |
| `rounded-full` | — | 머리글자 원, 필터 칩, `예시` 표지 |

**경계와 높이**

| 단계 | 라이트 | 다크 | 쓰는 곳 |
| --- | --- | --- | --- |
| 0 | `canvas` | `canvas` | 바탕, 옆 메뉴 |
| 1 `shadow-elev-1` | 고리 + `0 1px 2px` ink 4% | 고리만 | 카드, 이슈 카드, 선택된 메뉴, 버튼, 검색창 |
| 2 `shadow-elev-2` | 고리 + `0 12px 32px -12px` ink 18% | 고리 + 검은 그림자 | 로그인 미리 보기, 팝업 |
| 패널 `shadow-panel` | 고리 + `0 16px 40px -12px` | 같음 | 이슈 패널 |

- 카드 안 줄 구분은 카드 안쪽 여백(20px)에서 시작하고 끝나는 1px `rule` 선입니다(`after:inset-x-5`). 표 머리에 회색 바탕을 깔지 않습니다.
- hover는 `hover` 바탕, 또는 이슈 카드처럼 고리를 `rule-strong`으로 진하게 합니다.

**움직임**

- 시간: 빠름 120ms(hover, 눌림), 보통 200ms(패널 열림, 펼침), 첫 화면 등장 280ms.
- 곡선: `cubic-bezier(0.2, 0.7, 0.2, 1)` 하나만(`ease-tool`).
- 첫 화면은 구역별로 30ms씩 늦춰 아래로 4px 떠오르며 나타납니다. 데이터가 다시 불러와질 때는 움직이지 않습니다.
- 막대(진행률, 부하)는 처음 그릴 때만 왼쪽에서 채워집니다.
- `prefers-reduced-motion: reduce`이면 모든 움직임을 끕니다.

- 표와 사람 목록은 화면 폭이 아니라 **카드 폭**(container query `@[35rem]` = 560px)으로 접습니다.
- 페이지 전체는 390px에서 가로로 스크롤되지 않습니다. 가로 스크롤은 탭 줄만 합니다.
- 들어가기 전 화면: 1024 이상 두 칸(왼쪽 폼, 오른쪽 `예시` 미리 보기), 1023 이하 폼만 한 칸.

## 6. 컴포넌트 규칙

### 틀 (옆 메뉴, 상단 막대)

- 틀(옆 메뉴, 상단 막대, 이슈 패널, 단축키)은 로그인과 회사 확인(`/api/me`)이 끝난 뒤에만 그립니다. 그 전에는 아래 "들어가기 전 화면"만 보입니다.
  빌드된 HTML에는 중립적인 "확인하는 중" 화면만 들어가고 메뉴 글자는 들어가지 않습니다.
- 옆 메뉴(1024px 이상): `canvas` 바탕, 오른쪽 1px `rule`. 맨 위에 회사 표식(32px, Mono 두 글자) + 회사 이름 + "업무 보드".
  메뉴 줄은 36px, 16px 선 아이콘 + 이름. 선택된 메뉴는 `surface` 바탕 + `elev-1` + 굵게. 마우스나 초점이 가면 오른쪽에 단축키(`g o` 등).
  맨 아래에 언어·밝기 토글과 단축키 요약(`/` 검색, `j` `k` 이동, `Enter` 열기, `Esc` 닫기).
- 상단 막대: 반투명 `canvas` + 흐림, 아래 1px `rule`, 스크롤해도 고정. 1024px 이상은 경로(`acme-health / 개요`), 검색창(`/`), 계정과 로그아웃.
  개발 모드에서는 계정 자리에 개발용 사용자 선택이 있습니다.
- 언어 토글과 밝기 토글은 같은 모양(`.seg`: `sunken` 바닥 위 선택된 칸만 흰 판)입니다. 언어 이름은 늘 그 언어로 쓰고, 639px 이하는 `KO` / `EN`(Mono). 밝기는 해·달 아이콘.

### 화면 머리

- `text-small` `muted` 한 줄(맥락) → `text-title` 제목 → `text-body` 한 문장. 굵은 줄을 긋지 않습니다.
- 개요는 맥락 줄(날짜 · 열린 일 · 주기, `·`로 구분) → `display` 한 문장 → 숫자 판 한 장(4칸 + 아래 팀 막대와 범례).

### 카드

- `.card`: `surface` 바탕, `elev-1` 고리, 12px 모서리. 머리: 제목(`heading`) + 개수(Mono `meta`) + `muted` 설명 + 오른쪽 이동 링크와 단축키. 머리 아래 선은 긋지 않습니다.
- 카드 안 목록은 줄 사이 안쪽 선, 좌우 20px. 빈 상태는 카드 안에 점선 상자.

### 표 (손봐야 할 일, 검색, 회의 노트)

- 열 머리 36px, `meta` `muted` 글자, 아래 1px `rule`. 바탕은 깔지 않습니다: `저장소 #번호 / 제목 / 상태 / 담당 / 경과`.
- 묶음 머리: 깃발 + 개수(Mono) + 이유(`muted`). 줄은 hover와 초점에 `hover` 바탕.
- 카드 폭 560px 미만에서는 한 줄이 세 줄로 접힙니다: 번호·경과 / 제목 / 상태·담당.

### 이슈 카드 (보드)

```
booking-api #102 · 작업            긴급
예약 조회 API 페이지네이션
이민준          PR 1 · 댓글 2 · 1일 전
```

- `surface`, `elev-1`, 10px 모서리, 안쪽 14 × 16. 첫 줄 Mono 번호 + Sans 종류, 제목은 `ui` 500 두 줄까지, 마지막 줄 담당자와 PR·댓글·경과(Sans).
- 완료 카드는 바탕 없이 고리만 남기고 제목을 `muted`로.
- 보드 열이 이미 상태를 말하므로 상태 줄은 생략합니다(필요하면 `showStatus`로 점 + 이름).
- 긴급이고 아직 할 일이면 왼쪽 3px 주홍 거터. 우선순위는 설정에서 켠 경우에만 보입니다. 높음은 `ink-soft` 글자 "높음"만.
- hover: 고리를 `rule-strong`으로 + 옅은 그림자. 클릭하면 이슈 패널(`?issue=`)이 열립니다. 카드 안에 다른 링크를 두지 않습니다.

### 보드 (내 작업, 프로젝트별, 사람별)

- 열 머리는 판 없이 점 + 상태 이름 + 개수. 열 수는 화면이 아니라 보드가 가진 폭으로 정합니다(`boardCols`, container query): 544px 미만 1열, 1024px 미만 2열, 그 이상 4열. 한 열이 240px보다 좁아지지 않게 하려는 것입니다.
- 사람별 보드는 사람마다 머리(머리글자 원, 이름, 진행·리뷰 수, 몰림 깃발) + 같은 열 묶음입니다. 한 열로 쌓일 때는 빈 열을 숨깁니다. 완료 열은 취소된 일만 있어도 비지 않은 것으로 봅니다.

### 상태 표시

- 기본형: 8px 점 + 상태 이름(`small`, `ink-soft`). 예: `● 리뷰 중`.
- 요약형: 진행률 막대, 또는 `완료 2 · 리뷰 중 3` 같은 점 붙은 숫자 줄(숫자는 Mono).
- 상태 이름은 할 일 / 진행 중 / 리뷰 중 / 완료 / 취소. 다른 말로 바꾸지 않습니다.

### 주의 표시

주홍을 쓰는 유일한 요소입니다. 모양은 **깃발**: 높이 22px, 주홍 글자 + 반투명 주홍 1px 고리 + 4px 모서리, 굵기 600.

| 종류 | 조건 | 표시 |
| --- | --- | --- |
| 긴급 | 우선순위 `urgent`이고 완료가 아님 | 깃발 `긴급` (`accent-wash` 바탕), 아직 시작 전이면 줄 왼쪽 3px 거터 |
| 멈춤 | 열린 이슈의 마지막 활동이 7일 이상 전 | 줄·카드 불투명도 0.55 + 경과 자리에 깃발 `12일째` |
| 담당자 없음 | 열린 이슈에 담당자가 0명 | 담당자 자리에 점선 원 + 주홍 글자 `담당자 없음` |
| 리뷰 대기 | 리뷰 요청된 열린 PR이 24시간 이상 | 묶음 머리 깃발 `리뷰 대기`, 경과 자리에 대기 일수 |
| 이슈 없음 | 회의 할 일이 이슈로 이어지지 않음 | 깃발 `이슈 없음` |

멈춘 줄은 흐려지지만 깃발은 흐려지지 않습니다. 흐려짐은 "잊혀 가는 중", 깃발은 "그래서 봐야 함"을 뜻합니다.

### 사람별 부하 막대

- 한 줄에 한 사람: 머리글자 원, 이름, 막대, 열린 수(Mono), 지금 하는 일 하나.
- 막대는 그 사람의 열린 일을 상태별로 쌓은 것입니다: 진행 중, 리뷰 중, 할 일(옅게). 길이의 기준은 팀에서 열린 일이 가장 많은 사람(100%).
- "몰림" 깃발: 진행 중 + 리뷰 중이 4건 이상이고 팀 중앙값의 2배 이상일 때만. 중앙값은 맡은 일 없는 팀원까지 포함해 셉니다.
- 맡은 일이 0건이면 막대 대신 `muted` 글자 "맡은 일 없음".

### 진행률 막대

- 높이 6px, 바닥 `sunken`, 모서리 3px. 완료 / 리뷰 중 / 진행 중 / 할 일 순서로 왼쪽부터 쌓습니다.
- 옆이나 아래에 숫자를 항상 함께: `완료 1/6 · 17%`. 막대만 두지 않습니다. 전체가 0건이면 "아직 일이 없습니다".

### 이슈 패널

- 오른쪽에서 열리는 560px 패널(휴대폰은 전체 너비), 왼쪽 모서리 16px. 머리 56px: Mono 번호 + `닫기 Esc` 버튼.
- 제목(`title`) 아래 속성은 고리 두른 2열 표(상태, 담당자, 종류, 주기, 우선순위, 크기, 마지막 활동).
- 그 아래 연결된 PR, 하위 일, 이 일이 나온 회의, 대화 구역. 구역 머리 아래 선은 긋지 않습니다.
- 열리면 닫기 버튼에 초점, 닫히면 연 자리로 초점이 돌아갑니다.

### 단축키

| 키 | 동작 |
| --- | --- |
| `/` | 검색창으로 이동 (검색창 안에서 `Esc`는 빠져나오기) |
| `g` 다음 `o` `m` `p` `b` `n` `s` | 개요, 내 작업, 사람별 보드, 프로젝트별 보드, 회의 노트, 설정 |
| `j` / `k` | 목록·표·보드에서 다음 / 이전 줄로 초점 이동(`data-row`가 붙은 요소) |
| `Enter` | 초점이 있는 줄 열기 |
| `Esc` | 이슈 패널 닫기 |

- 글자 키는 키 위치(`KeyboardEvent.code`: `KeyG`, `KeyJ`, `KeyO` 등)로 판정합니다. 한글 입력 상태에서도 같은 자리의 키로 동작합니다. `/`는 `key` 또는 `Slash`로 판정합니다.
- 입력창, 선택 상자에 글자를 넣는 중이거나, 한글 조합 중이거나, Ctrl·Cmd·Alt·Shift를 누른 채면 동작하지 않습니다.
- `j`/`k`는 옮겨 갈 줄이 있을 때만 키 입력을 가로챕니다. 이슈 패널이 열려 있는 동안 `/`, `g`, `j`, `k`는 꺼집니다.
- 화면에 보여 주는 단축키(`kbd`)는 모두 실제로 동작해야 합니다. 새 목록을 만들면 줄에 `data-row`를 붙입니다.

### 빈 화면, 들어가기 전 화면, 오류

- **빈 화면**: 한 문장으로 사실을 말하고, 좋은 소식이면 그렇다고 말합니다. `muted` 글자 + `rule-strong` 점선 상자(10px 모서리).
  보드의 빈 열은 상자 없이 `muted` "없음" 한 줄.
- **들어가기 전 화면**(`/login`, 확인 중, 회사 없음, 회사 선택, 세션 만료, 오류, 로그인 마무리, 개발 모드 선택): 틀 없는 단독 화면(`GateFrame`).
  - `canvas` 바탕 전체. 왼쪽 위에 `wb` 표식(28px) + "업무 보드", 오른쪽 위에 언어·밝기 토글, 맨 아래 `muted` `meta` 표어 한 줄. 검색, 단축키, 메뉴는 없습니다.
  - 가운데 440px 기둥을 세로 가운데에: 짧은 선 + `small` 머리(로그인, 회사 확인, 연결 등) → `display` 제목 → `body` 한 문장 → 16px 모서리 카드 하나(안쪽 24px).
  - 카드 안 주 동작은 48px 잉크색 버튼 하나(폭 전체).
  - `/login`은 1024px 이상에서 두 칸이고, 오른쪽 `sunken` 판에 한 문장 현황 미리 보기를 둡니다. 미리 보기는 오른쪽 위 `예시` / `Example` 표지와 아래 "예시 데이터입니다" 한 줄로 실제 데이터가 아님을 밝힙니다. 1023px 이하에서는 그리지 않습니다.
  - 회사 없음, 회사 선택 화면은 카드 아래에 `small` `muted` 한 줄 "<로그인> 계정으로 로그인함 · 로그아웃".
  - 화면이 바뀌면 초점이 제목(`h1`, `tabIndex=-1`)으로 갑니다. 화면마다 `<main>`과 `h1`은 하나입니다.
  - 세션이 끝나 돌아왔으면 로그인 카드 맨 위에 안내(`Notice`)를 둡니다. 네트워크·서버 오류는 로그아웃으로 보지 않고 "다시 시도" 화면을 보여 줍니다.
- **개발 모드**(Supabase 설정 없음): 같은 틀의 `/login` 카드에서 개발용 사용자를 고르고(48px 선택 상자), 실행 방법은 카드 안에 접어 둡니다.
  "업무 보드" 옆에 "개발 모드" 표지(1px `rule-strong` 고리)를 둡니다.
- **오류**: 주홍을 쓰지 않습니다. `ink` 글자 + 왼쪽 2px `ink-soft` 줄 + 해결 방법 한 줄.
- **불러오는 중**: 회색 빈 줄(skeleton) 대신 카드 머리는 바로 그리고 내용 자리에 `muted` "불러오는 중…".

### 말

- 지라 용어 금지: Epic → 큰 목표, Task → 작업, Backlog → 대기 목록, Sprint → 주기, Story point → 크기.
- 버튼은 동사로 끝냅니다: "이슈로 만들기", "보드에서 보기".
- 숫자 뒤에 단위: "3건", "12일째", "2일 전".

### 언어

- 화면 언어는 한국어(`ko`)와 영어(`en`) 두 가지입니다. 고른 값은 `localStorage`의 `workboard.lang`에 두고, 처음 오면
  브라우저 언어가 `ko`로 시작할 때 한국어, 아니면 영어입니다. 고른 언어는 `<html lang>`에 들어가고, 줄 간격도 이 값을 따릅니다.
- 화면 문구는 모두 `web/src/lib/i18n/ko.ts`(원본)와 `en.ts`에 둡니다. 컴포넌트에 문구를 직접 쓰지 않고 `useT()`로
  꺼내 쓰며, 날짜·경과·숫자는 `useFormat()`(`Intl`)으로 만듭니다. 한쪽에만 있는 키는 `tsc`가 막습니다.
- 사용자가 쓴 내용(이슈 제목, 댓글, 회의 노트, 저장소·사람 이름)은 번역하지 않습니다.
- 영어도 지라 용어를 피합니다: Epic → Goal, Sprint → Cycle, Story point → Size. 상태는 To do / In progress /
  In review / Done / Canceled. 짧고 담백한 개발 도구 말투로, 셀 수 있는 말은 단수·복수를 맞춥니다("1 issue", "3 issues").
- 좁은 칸(손봐야 할 일의 경과, 최근 흐름의 시각)은 영어에서 짧은 꼴("3d ago")을 씁니다.

## 7. 토큰

값은 `web/src/app/globals.css`에 있고, 이 문서 2~4장의 표와 같아야 합니다. Tailwind 4의 `@theme inline`으로 연결해
`bg-canvas`, `bg-surface`, `text-ink`, `text-faint`, `bg-on-ink`, `border-rule`, `bg-hover`, `bg-status-review`, `text-accent`, `font-mono`,
`text-display` … `text-meta`, `text-figure`, `rounded-control` / `rounded-item` / `rounded-card` / `rounded-sheet`, `shadow-elev-1`, `shadow-elev-2`,
`shadow-panel`, `ease-tool` 같은 클래스가 생깁니다.

- 줄 간격은 `--lh-*` 변수에 있고 `:root[lang="en"]`과 639px 이하에서 바뀝니다. `text-*` 클래스가 이 변수를 씁니다.
- 다크 값은 `@media (prefers-color-scheme: dark)`의 `:root:not([data-theme="light"])`와 `:root[data-theme="dark"]` 두 곳에 같게 둡니다.
  기본은 OS 설정을 따르고, 밝게·어둡게 토글이 `<html data-theme>`를 고정하면 그쪽이 우선합니다.
- 이슈 패널 뒤 어둑한 막은 `--wb-scrim`(라이트 `rgb(14 16 19 / 0.32)`, 다크 `rgb(0 0 0 / 0.55)`)입니다.
- 공용 클래스: `.card`(판), `.btn` / `.btn-primary` / `.btn-lg`(버튼), `.seg`(두 칸 토글), `.flag` / `.flag-fill`(주의), `.gutter`(왼쪽 주홍 거터),
  `.kbd`(단축키), `.bar`(막대), `.link`, `.tabs`(스스로 스크롤하는 탭 줄), `.reveal`.
- 상태 색은 코드에서 한 곳(`web/src/lib/labels.ts`의 `STATUS_DOT`)에서만 클래스 이름으로 연결합니다.

## 8. 화면을 만들 때 확인할 것 (PR 체크리스트)

PR 설명에 아래 항목을 복사해 확인 표시합니다.

- [ ] 새 화면을 만들기 전에, 기존 화면이나 이슈 패널에 붙일 수 없는지 먼저 따졌다(흩어지면 아무도 안 봄).
- [ ] 화면 맨 위가 "이 화면에서 가장 중요한 사실 하나"를 말한다.
- [ ] 색은 토큰만 썼다. `slate-*`, `blue-*` 같은 Tailwind 기본 색이나 16진수 값을 직접 쓰지 않았다.
- [ ] 글자 크기는 2장의 단계(`text-display` … `text-meta`)에서만 골랐다. `text-[12.5px]` 같은 임의 크기가 없다.
- [ ] Mono는 ASCII(번호, 숫자, 단축키)에만 썼다. 날짜·경과·한글은 Sans다.
- [ ] 주홍(`accent`)은 주의 표시에만 썼고, 한 화면에 칠해진 면이 3곳 이하다. 주 버튼은 잉크색 하나다.
- [ ] 상태는 점 + 이름으로 보이고, 이름이 할 일 / 진행 중 / 리뷰 중 / 완료 / 취소(영어 To do / In progress / In review / Done / Canceled) 중 하나다.
- [ ] 새 문구는 `ko.ts`와 `en.ts`에 함께 넣었고, 영어로 바꿔도 넘치거나 줄이 깨지지 않는다.
- [ ] 지라 용어가 없다. 고급 필드(주기, 크기, 우선순위)는 설정에서 켠 경우에만 보인다.
- [ ] 이슈가 보이는 모든 곳은 클릭하면 이슈 패널(`?issue=`)이 열린다. 목록 줄에는 `data-row`가 있어 `j`/`k`로 갈 수 있다.
- [ ] 화면에 보여 준 단축키는 모두 동작하고, 입력 중에는 동작하지 않는다.
- [ ] 빈 상태, 불러오는 중, 오류 문구를 모두 넣었다.
- [ ] 라이트와 다크, 한국어와 영어 모두에서 확인했다.
- [ ] 390 / 768 / 1280px에서 5장 규칙대로 바뀌고, 390px에서 페이지 가로 스크롤이 없다(탭 줄만 스크롤).
- [ ] 키보드로 모든 클릭 대상에 갈 수 있고 초점 테두리가 보인다.
- [ ] 움직임은 4장 규칙 안이고 `prefers-reduced-motion`에서 꺼진다.
